# 提示词版本化与回归（Prompt Versioning and Regression）

- 节点标识：PE-E-09
- 英文名：Prompt Versioning and Regression
- 所属分组：G05 评测与自动优化
- 依赖深度：第 21 层
- 内容状态：内容已写满
- 标签：版本化、回归、基线

## 为什么需要它

为什么必须给提示词做版本化与回归：提示词不是一次写定的文档，而是会被反复微调的活资产；改动频率越高，退化就越可能以「感觉不如以前」的模糊抱怨形式出现，而不是一条明确的报错。若没有版本标识，就没有任何手段把两次质量差异归因到某一次具体改动，团队只能在若干候选版本之间反复猜测。版本化提供可定位性，回归提供可比较性，二者缺一，改动就退化为凭印象的赌博。同时，回归必须覆盖成本与延迟：提示词改动经常在准确率上换来小幅提升，代价却是显著更高的 token 消耗，只盯质量指标会把这类隐性涨价当成改进放行。

**适用边界**

版本化与回归提供质量的可追溯性；它保证改动可比较、可归因、可回滚，但不评价某个提示词写法是否优雅，也不替代人工对失败样本的逐条判读。

## 机制说明

把提示词当作代码资产来管理，需要三个并列的版本标识：提示词文本自身的版本、评测集与基线的版本、以及二者之间的对应关系；缺少其中任何一个，历史数字都会变成无法解释的孤证。一次完整的回归有固定动作顺序：先记录当前基线，再改动提示词，然后在同一评测集上重跑，与基线逐项比较，给出接受或拒绝的判定，最后把结论连同两个版本标识一起留档。工程上有三条容易漏掉的要求。其一，评测集本身也必须版本化，否则样本一换，新旧分数就不可比；其二，指标不能只有准确率，还要同时跟踪成本与延迟，因为大量提示词改动本质上是用更多 token 换取更高通过率，只看质量会把涨价误判为进步；其三，更换模型后必须重建基线，旧模型上的分数不能沿用，否则模型能力差异会被记成提示词改动带来的涨跌。配套的工程习惯是把提示词从散落在代码里的字符串提升为独立、受版本控制的资产，让评审、灰度与回滚都能机械执行。

## 何时该用 / 何时不该用

- 任何提示词改动进入生产前：先记录基线版本，再改提示词，在同一评测集上重跑并与基线逐项比较。
- 更换模型或模型版本时：重建基线，避免把模型侧的能力差异误记成提示词改动的涨跌。
- 不适用于只跑相关用例：抽样运行会漏掉交叉影响，全量评测集须按固定周期重复执行。
- 不适用于只跟踪准确率：提示词改动常以成本换质量，必须同时记录成本与延迟两项指标。

## 实验台

### shell（bash）

```bash
cd 04-prototype/16-checkpoint
cat > _wave3_solo/PE-E-09/regression-log.txt <<'EOF'
prompt_rev: <git 短哈希，提示词文本的版本标识>
evalset_rev: <git 短哈希，评测集与基线的版本标识>
model: <模型名与版本号>
EOF
sha256sum <提示词文件> <评测集文件> | tee -a _wave3_solo/PE-E-09/regression-log.txt
git rev-parse --short HEAD | tee -a _wave3_solo/PE-E-09/regression-log.txt
cat _wave3_solo/PE-E-09/regression-log.txt
```

预期观察：回归记录里同时出现提示词与评测集两个版本标识、模型名与版本号、以及哈希或提交号；三者齐备，历史分数才可比较。任一缺项即视为本次改动不可判定，不能进入生产。

### prompt（markdown）

```markdown
你是一名评测记录员。输入是同一评测集上的基线结果与新版本结果两份逐样本分数，以及本次改动说明。请只依据输入作答，不引入外部知识。要求：一，逐项列出准确率、成本、延迟三项指标的基线与新值，并给出差值方向；二，指出每一项退化所波及的样本类别；三，给出接受、拒绝或重跑三种判定之一，并说明依据；四，若两份结果的评测集版本标识不一致，直接判定为不可比并停止比较。
```

预期观察：输出含三项指标的基线值、新值与差值方向，退化项指明波及的样本类别，并给出接受、拒绝或重跑之一的判定与依据；当两份结果的评测集版本标识不一致时，回答必须判为不可比而不是继续比较分数。

## 证据

- **官方已明确把生产提示词归入应用代码管理，并给出提示对象 API 的关停时间线，这构成提示词必须版本化的直接依据。**（S-0012，official）
  - 出处：https://developers.openai.com/api/docs/guides/latest-model
  - 原文关键句：OpenAI is deprecating reusable prompt objects in the API. Prompt creation will be de-emphasized beginning June 3, 2026, and `v1/prompts` is scheduled to shut down on November 30, 2026.
- **提示词与提示风格改动会在质量与成本之间换位，且步骤式推理一类风格并非普遍增益，故回归必须同时看成本与延迟。**（S-0037，paper）
  - 出处：https://arxiv.org/abs/2507.13525
  - 原文关键句：For high-performance LLMs, simple prompts often outperform more complex ones while reducing cost.
- **官方公布的内部评测显示精简系统提示词可同时提升评分并大幅削减 token 与成本，说明提示词改动确实以成本换质量，其数字必须逐版留档。**（S-0012，official）
  - 出处：https://developers.openai.com/api/docs/guides/latest-model
  - 原文关键句：In a sample of internal coding-agent eval runs, configurations with leaner system prompts improved evaluation scores by roughly 10–15% while reducing total tokens by 41–66% and cost by 33–67%.

## 术语

- **提示词版本化与回归（Prompt Versioning and Regression）**：把提示词当作代码资产纳入版本控制，并在每次改动后跑同一评测集对比基线，防止无声退化。
- **换模型即失效与重编译（Model Swap Invalidates and Requires Recompilation）**：提示词中的多数经验与具体模型绑定；更换模型后必须重跑评测并重做优化，而不是沿用旧结论。

## 失效模式

- 不记录版本标识：只保留文本最新版，线上退化后无法判定是哪一次改动造成的，只能整包回退并重跑全部验证。
- 评测集被悄悄改动：历史基线随之失去可比性，新旧分数放在一起比较会得出方向性错误的结论。
- 只跑相关用例：交叉影响被漏掉，主路径指标保持好看，边缘样本已经在静默退化。
- 换模型后沿用旧基线：把模型侧的能力差异记成提示词改动的涨跌，据此接受一个实际更差的提示词。

## 一句话小结

把提示词与评测集一并版本化，每次改动跑同一评测集对照基线，并同时记录成本与延迟；换模型后必须重建基线，使评审与回滚都能机械执行。
