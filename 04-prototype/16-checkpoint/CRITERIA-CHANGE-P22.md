## 2. 根因（两层，均为契约侧）

1. **配额是阶段守卫，其前件在内容填充期消失**。「`registered ≥60`」要断言的是**注册期**的事实：「绝大多数节点还没内容」。它的作用是防止「架构未定就落页」。一旦进入内容填充期（`CONTINUE-PROMPT-D4.md:45` 明写「当前处于**内容填充期**」），被断言的既有状态**注定要变**——这不是数据出问题，而是**判据的适用阶段结束**。
2. **用数量代理「状态与内容是否一致」**。真正要防的失败模式是**说谎的状态**：
   - 「内容已填却仍标 `registered`」⇒ 页内徽标「架构在册 · 内容待填充」与实际不符，且节点页不落盘（内容白写）；
   - 「半填」（`lab` 填了、`evidence` 空）⇒ 页面渲染出 `本轮未写。` 占位。
   数量配额**看不见这两种**：它只看两态各多少个。⇒ 按 `SCHEMA.md` §3 的分档原则，应**换判据**（换成能看见目标失败模式的那条），而不是调数字。

**第三层（自检盲区）**：旧配额在门控与数据侧各写一份且**值不同**，而数据侧那份更严（`==3` + 固定名单）——两份都无人逐轮跑数据侧 ⇒ 差异与「一个都不能翻」这一事实直到本轮要做内容时才暴露。

## 3. 裁决表（改契约，⛔ 不改主线目标）

| # | 变更 | 依据 |
|:--:|---|---|
| C1 | **保留** `complete ≥ 3` 为硬判据（门控 + 数据侧**同值**） | 理由成立且与内容质量有因果关联：须覆盖三种内容形态（被证伪的技巧 / 机制型原理 / 落地实践）。★ 它是**下限**，内容波次只会把它推高，不成阻塞 |
| C2 | **撤销** `registered ≥ 60`（门控）与 `REGISTERED_MIN`（数据侧）；**撤销** C24 的 `== 3`、C25 的 `len(nodes) - 3`、C27 的固定名单 | 数量配额**无因果依据**（全仓无推导），且其阶段前件已消失；固定名单等价于「禁止任何新内容落页」，与主线直接冲突。★ 判别句检验：**若把数据改成符合它**（不翻态、不落页）会**降低**内容质量（64 个节点永远不可点入）⇒ 问题在阈值不在数据 |
| C3 | **换成双向一致性**（★ 在**「状态是否说谎」这一维度**比旧配额更严；⚠ **在「内容是否够厚」这一维度更宽**——见 §5 局限与 §4 的审核反例，⛔ 不得读作「全面更严」） | 见下表 |
| C4 | 数据侧与门控**同源同值**（消除 `>=60` vs `==3` 的双实现漂移） | 消除「同一契约两份实现」这一类缺陷 |

**C3 新判据（`check_p22` / `_selfcheck.py` 两侧同实现）**：

| # | 断言 | 防的失败模式（旧配额看不见的） |
|:--:|---|---|
| ① | `complete` 节点 **8 区块全非空**（why / intro / when / lab / evidence / terms / pitfalls / summary） | 翻态却留空块（保留原断言） |
| ② | **`registered` 节点的 `lab` / `evidence` / `pitfalls` 必须全为空** | ★ **半填**：内容填了却仍标「待填充」；也是「已填但不落页」的当场报警 |
| ③ | `complete` + `registered` = 全量注册数；`content_status` ∈ 闭集 | 状态越界/漏登 |
| ④ | `pending_nodes` **集合等于** `registered` 集合（`P13` 已在跑） | 漏登记（保留） |
| ⑤ | `registered` 节点仍须过 `why`/`intro` 下限与 `summary` 结构性三条；`complete ≥ 3` | 保留的全部内容下限（⛔ 未动） |

## 5. 局限登记（⛔ 必须明说）

0. ★ **审核当场给出一条反例（2026-10-16，第 5 轮；主 Agent 复核成立）**：取一个 `registered` 节点翻成
   `complete`，把 `lab`/`evidence`/`pitfalls` 填成**垃圾但非空** ⇒ `check_p22` / `check_p05` / `check_p06`
   **三项全 PASS**；而**旧配额**在同一状态下会 FAIL（翻转后 `registered = 58 < 60`）。
   ⇒ **本变更在「内容薄不薄」这一维度上比旧配额更宽**。「更严」只成立于**一致性维度**：
   旧配额看不见「内容已填却仍标 `registered`」（状态说谎）与「半填」，新判据当场判 FAIL。
   ⛔ 本登记件的 C3 行已据此改写；⛔ 不得再概括成「新判据比旧配额更严」。

1. **本变更删掉一条下限**，因此它不再阻止「某轮把许多节点一次性翻态而每页内容薄弱」。补偿是分层的：`why`/`intro` 的 caliber 下限（P05）、8 区块非空（P22 ①）、`pitfalls`/`evidence` ≥1（P06）、每页结构与自制图（P35 ④⑤⑧）、MD 镜像（P13）。**但「内容厚不厚」这一面不可机检**——与 `G8`（长文可扫性）同档，由真实渲染（P38 的 PNG 证据）+ 人看兜，⛔ 不得声称门控覆盖了它。
2. **旧配额从未有负例夹具** ⇒「它曾经有效」这一说法**不可考**；本变更**不主张**发现了旧的回归，只主张旧的代理目标错位。
3. 本变更**不改**内容产出的任何数值阈值（`why`/`intro`/`summary`/`quote` 等的值一个未动）。
4. `complete ≥ 3` 的「3」是**内容形态数**，不是实测阈值；它的正当性来自形态覆盖而不是量纲推导，⛔ 不得据此把其它数字也按「3」来定。

## 6. 纪律自陈

> 本变更的正当性来自**原阈值的适用阶段结束 + 数量代理看不见目标失败模式**，而非"数据过不了"。
> 判别标准（沿用 `CRITERIA-CHANGE-P05.md` §6）：*若把数据改成符合原阈值会**降低**内容质量，则问题在阈值不在数据。*
> 本次正是这种情形——把数据改成符合 `registered ≥60` 意味着**64 个节点永远不可点入**（内容波次被禁止），故换判据（C3），
> 并**同批补上比旧配额更严的一致性断言与负例夹具**（C3 ② + `mut_p22` 新增条目），而不是简单地把 60 改成 0。
> ⛔ 本轮**未**为变绿放宽 P38 / P35 / P05 / P06 的任何阈值；⛔ 未新增豁免；⛔ 未把保留项删除（C1 / C3 ①③④⑤ 全部原样保留）。
