# 生成者—评估者（Generator–Evaluator）

- 节点标识：PE-O-05
- 英文名：Generator–Evaluator
- 所属分组：G04 编排
- 依赖深度：第 12 层
- 内容状态：内容已写满
- 标签：编排、评估者、迭代

## 为什么需要它

生成者—评估者模式把产出与判定分开，用明确判据驱动迭代，是让「改进」可被度量的编排形态。它的质量上限由判据质量决定，而不是由迭代次数决定：判据含糊时，迭代会退化为风格漂移。因此这一模式的第一项工程动作不是加迭代，而是先把判据写成可判定的检查项。

**适用边界**

该模式要求评价标准可被写成可判定的条件；对没有明确标准的开放创作任务，评估者的判断不稳定，此时应改用人工抽检或用户反馈而非自动迭代。

## 机制说明

模式的实现要素是：生成者的产出契约、评估者的评分准则与反馈格式、迭代终止条件、以及成本上限。评估者可以是有明确准则的模型、独立模型、或外部校验器，其可靠性依次递增。工程要点有三条：其一，评分准则必须可判定，否则评估者会退化成偏好表达；其二，反馈要具体到可执行的修改点，笼统的「再改进一下」不会带来增益；其三，必须设迭代上限并记录未收敛样本，否则成本不可控。该模式与反思回路的区别在于职责分离：反思由同一个执行者完成，生成者—评估者由两个角色完成，因此后者对自评偏差的抵抗力更强。

## 何时该用 / 何时不该用

- 评价标准可写成可判定条件时：该模式能稳定驱动迭代改进。
- 需要把「变好了」变成可度量过程时：把判据与迭代记录一并留档。
- 不适用于开放创作类任务：无明确标准时评估者判断不稳定。
- 不适用于不设迭代上限：必须绑定轮数上限与未收敛样本记录。

## 实验台

### prompt（markdown）

```markdown
你是评估者，只评分和指位置，不改写产出。

## 评分卡（四项各 0–2 分，满分 8 分）
1. 事实可核验：每条断言都能在给定材料里找到出处。
2. 格式合规：产出满足约定的字段与顺序。
3. 可执行性：修改建议指向具体句子，而不是「再优化一下」。
4. 边界声明：写出了未覆盖的情况。

## 评分卡之外必须输出
- 未通过项对应的原文片段（逐字引用，不要改写）
- 判定为「不可判定」的项，并说明缺什么材料才能判定

## 终止条件
总分 ≥ 7，或迭代满 3 轮，二者先到为准。满 3 轮仍未达 7 分，标记为未收敛样本并保留每轮分数。
```

预期观察：对同一份产出连续评分两次，两次总分相差不超过 1 分；连续 3 轮未达 7 分的样本被写入未收敛清单并带每轮分数。

### file（python）

```python
import json

LOG = 'eval_log.jsonl'  # 每行一个 {"round": 1, "score": 6, "failed_items": [...]}
rows = [json.loads(l) for l in open(LOG, encoding='utf-8') if l.strip()]

assert rows, '空日志：没有记录任何一轮评分'
assert all(0 <= r['score'] <= 8 for r in rows), '分数越界：评分卡满分是 8'
assert rows[-1]['round'] <= 3, '迭代轮次超过上限 3'
assert all('failed_items' in r for r in rows), '有一轮没记未通过项，反馈不可执行'

unconv = [r for r in rows if r['score'] < 7]
print('轮次 %d / 未达 7 分的轮次 %d' % (len(rows), len(unconv)))

```

预期观察：对一份合规日志运行，脚本打印轮次与未达 7 分的轮次数并以退出码 0 结束；把最后一行的 round 改成 4、或把某行 score 写成 9，脚本抛 AssertionError。

## 术语

- **生成者—评估者（Generator–Evaluator）**：由生成者产出、评估者按明确判据给出反馈并驱动迭代的编排模式，适用于有清晰评价标准的任务。
- **模型即裁判（LLM-as-a-Judge）**：用模型按评分准则对输出打分或排序的评测手段；存在位置偏差、冗长偏好与自我偏好等系统性偏差，须与确定性断言并用。

## 失效模式

- 评分准则写成「是否清晰」这类不可判定词：两轮评分给出互相矛盾的分数，迭代方向随之随机漂移。
- 评估者与生成者共用同一份上下文与同一个模型：自评偏差被放大，分数一路上升而真实质量原地不动。
- 不设迭代上限：生成者反复改写同一段，成本持续上升，最终产出与第一版无实质差别。
- 反馈只写「再改进一下」：生成者拿不到可执行的修改点，下一轮改动落在措辞而非未通过项上。

## 一句话小结

质量上限由判据质量决定，判据一旦含糊，迭代就会退化为风格漂移。
