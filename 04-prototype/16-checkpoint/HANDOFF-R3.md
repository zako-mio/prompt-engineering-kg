## 三、元纪律（第 2 轮确立，第 3 轮起**必须沿用**）

1. **判据分档原则**（`SCHEMA.md` §3）：数值阈值只在能说清「把数据改成符合它会**改善**内容」
   时才作硬判据；否则降为**报告项**（逐条打印，⛔ 不判 FAIL）。
   判别句：*若把数据改成符合该阈值会**降低**内容质量，则问题在阈值不在数据。*
2. **判据作用域须与对象对齐**（R-23）：⛔ 不得整页扫替代区块切片；**代理判据**必须显式标注
   「代理对象 / 直接量 / 失效面」。
3. **取经须分清「范例」与「它自己的缺陷」**（HANDOFF-R2 §五 T8）：照抄外站结论会写出
   在本站不成立的因果。
4. **门控自身也会错，且以红灯形式骗人**：夹具必须 **fail-closed**（锚点全站找不到即抛错），
   让「锚点过期」与「判据恒真」分开暴露。
5. **子 Agent 的失败通知 ≠ 进程已停**：动同一批文件前先确认（落盘前跑静默期侦察）。
6. **门控全绿只说明「判据覆盖的面没问题」**，不说明「该看的面都被覆盖了」。
7. ★ **本轮新增：「环境能力不可用」这个结论本身也要复核**（R-21）：把「不可用」当成
   **待验证的假设**，下结论前先问「我失败的是哪一层？有没有别的后端？这条失败文案是不是
   兜底文案？」—— ⛔ 只允许「跑过 `_probe_env.py` 之后的事实」。
8. ★ **本轮新增：验证通道自身必须先被验证**（R-22）：一个会「假绿」的通道比一个会报错的
   通道**危险得多**。⇒ 截图类证据一律补**像素读数**（尺寸 / 唯一色数 / 亮度区间 / 字节）。
9. ★ **本轮新增：委派方自报 ≠ 读数**（R-24）：子 Agent 的「完成」按其**开工时刻**的世界观
   交付 ⇒ 主 Agent 须按**收口时刻**复核其**事实陈述**，⛔ 不整段采信。
