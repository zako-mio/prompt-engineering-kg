## 1. 触发事实（用户反馈原文两条）

| # | 用户原话 | 指向 |
|:--:|---|---|
| 1 | 首页的标题字号太大，不能一行内显示，不能两端稍微留空 | 根入口 `h1` 的字号令牌取值 |
| 2 | 左侧边栏可以占用整个竖直部分空间（本身那里也是空的），然后调整位置和放置更多开关 | 宽屏 `rail` 的形态与开关落点 |

第 3 条（内容排布）用户明确"等会再看" ⇒ 本轮⛔ 不动内容排布。

## 2. 根因（两条各自独立，均为**可复算的成因**，非观感口味）

### 2.1 标题折行：字号令牌取值与内容列宽无因果绑定

- 旧 `--fs-hero` 直接照抄 hub：`clamp(2.25rem, 1.2rem + 3.9vw, 4rem)` ⇒ 宽屏上界 **64px**。
- 根入口 `h1` 文案＝`meta.mission`＝「新一代提示词工程知识全景图与教程」＝**16 个汉字**；
  CJK 每字进宽 = `1em`，`h1` 的 `letter-spacing: -0.035em` ⇒ 行宽 = `16 × fs × 0.965`。
- 宽屏内容列宽 = `--container 1120` − `--rail-w 252` − `2 × --space-5 32` = **804px**。
- 旧值行宽 = `16 × 64 × 0.965` = **988px > 804px** ⇒ **必然折行**（用户所见）。
- 根因不是"hub 的 4rem 错"——hub 的落地页标题短得多；**根因是本站直接沿用了外站的字号值，
  而本站的标题字数与内容列宽都不同**，从未按本站版式复算过。

### 2.2 宽屏左栏：形态缺陷 ＋ 一处既有功能缺口

- `rail` 只 `align-self` 默认（`start`）⇒ 栅格行高由正文决定，而 rail 自身背景**止于内容高度**；
  内层 `100dvh` sticky 只保证"视口内常驻"，**不保证"整页竖向铺满"** ⇒ 长正文页的下方左侧留白。
- ★ **既有功能缺口（本轮实测发现，用户未提及但同源）**：`≥1180px` 档 `.site-head{display:none}`
  会把**顶部导航连同两枚显示开关一起藏掉**，而 rail 里当时**没有任何开关** ⇒
  **宽屏用户没有任何切换主题/动效的入口**。这不是"开关位置不好看"，是**功能不可达**。

## 3. 裁决

| # | 变更 | 依据 |
|:--:|---|---|
| C1 | **改写令牌 `fs.hero`**：`clamp(2.25rem, 1.2rem + 3.9vw, 4rem)` → `clamp(1.5rem, 0.6rem + 2.2vw, 3rem)` | 按**本站**宽度预算反解：`fs ≤ 804 / (16 × 0.965) = 52.1px`；取 `3rem`(48px) 使两端各留 31.4px。⛔ 未新增第 7 档字号令牌（守住"字号只用 6 档"），只改值 |
| C2 | **rail 撑满整页竖向**：`≥1180` 档加 `align-self: stretch` | grid 行高 = 正文高度 ⇒ 侧栏面板覆盖整页；内层 `100dvh` sticky 保持"视口内常驻" |
| C3 | **rail 内层改纵排 flex**：`display:flex; flex-direction:column`；新增 `.rail__foot{margin-top:auto}` | 导航在上、显示设置**锚在底端**（`margin-top:auto` 不引入任何令牌外字面值） |
| C4 | **两枚显示开关搬入 rail 底端**，顶部导航**保留同一组** | 堵 §2.2 的功能缺口。两处副本由 `display:none` **互斥**（基础档 `.rail{display:none}` / 宽屏档 `.site-head{display:none}`）⇒ 任一宽度档下**可见实例恰 1 组**；⛔ 与"同一组**路由**不得出现两处可交互实例"不冲突——开关是显示偏好、不是路由 |
| C5 | **侧栏内开关改纵向堆叠**（`.rail .switch{flex-direction:column;align-items:stretch}`） | 252px 侧栏里三枚胶囊横排必然溢出；纵排后按钮宽度拉满，触控目标 ≥44px 且更易点 |
| C6 | **新增判据 P34** | 把上述三条**可复算的成因**判据化（见 §4）；⛔ 不写"字号好看"这类不可判假的话 |
| C7 | **页脚移入 `.layout` 之内**；宽屏档 `rail` 跨第 1–2 行、页脚 `grid-column:1 / -1` 独占第 2 行 | ★ 中间态实测发现：只给 `align-self:stretch` 时 rail 的拉伸范围**止于正文底**——页脚当时在 `.layout` **之外**，于是页脚旁仍是空档（与 C2 的目标相抵）。把页脚收进栅格第 2 行后，rail 跨 1–2 行 ⇒ **整页竖向铺满**。连带：`.layout>.site-foot .wrap` 收回横向内边距（窄屏档由 `.layout` 提供，否则叠成两倍），宽屏档改由 `.site-foot` 自带 `--space-5` 内边距，使页脚左缘与正文左缘仍在同一竖线上 |
| C8 | **新增「背景素材：开 / 关」开关**（用户走查第 2 轮追加） | 摄影背景层是纯装饰，长文阅读时它是干扰源。`off` ⇒ `:root[data-backdrop="off"] .backdrop{display:none}`（与 P27 的「非当前主题帧 `display:none`」同规，⛔ 不用 opacity/visibility）。默认 `on` **不落属性、不落 localStorage 键** |
| C9 | **新增「正文字号：标准 / 大」开关**（用户走查第 2 轮追加） | 可读性偏好。大档 `1.125rem`（16→18px）走**新令牌 `--fs-body-lg`**——因为 P23 禁止令牌块之外声明自定义属性、P24 禁止令牌外 `font-size` 字面值，大档只能作为真令牌存在。★ 作用域刻意只覆盖 `body` 继承面：标题/导航/标签各自走自己的字号令牌，⛔ 不随正文档缩放（否则根入口 h1 被放大到 54px 会重新折行，直接顶掉本判据的宽度预算） |
| C10 | **窄屏档把 10 枚开关收进原生 `<details>` 折叠件**（`<summary>显示设置</summary>`） | 四组开关横排会把 sticky 头部撑成三四行。`summary` **本来就在**交互作用面登记表内（`summary:hover` 已登记）⇒ ⛔ 不新增任何 `:hover` 选择器。侧栏（≥1180）则用**两列栅格**排布：单列堆叠会把侧栏撑到 ~930px 高、在 900px 视口里被截断 |

## 4. P34 断言的四层（每条都必须可判假）

| 层 | 断言 | 防的失败模式 |
|:--:|---|---|
| a1 | 宽屏档存在 `.rail{display:block;align-self:stretch}` | 侧栏回落成"止于 100dvh"的半截面板 |
| a2 | 基础档存在 `.rail{display:none}`，宽屏档存在 `.site-head{display:none}` | 两套导航/开关同时可见（互斥被破坏） |
| a3 | `.rail__in` 为 `sticky + 100dvh + flex 纵排`；`.rail__foot` 有 `margin-top:auto` | 侧栏不能常驻视口 / 显示设置不锚底 |
| a4 | 宽屏档 `.rail` 含 `grid-row:1 / span 2`，`.layout>.site-foot` 含 `grid-column:1 / -1`；且**每一页**的 HTML 满足 `</footer></div></body>`（页脚是 `.layout` 的最后一个子元素） | 左栏拉伸范围止于正文底、页脚旁留空档（C7 的中间态） |
| b | **每一页**的 rail 子树与顶部导航子树各含**四组开关的全部档位**（主题 3 / 动效 3 / 背景 2 / 字号 2） | 宽屏档开关不可达（§2.2 的缺口回归）；或新增开关只落在单侧 |
| b2 | `<head>` 的 pre-paint 脚本含四个偏好键（`ui-theme` / `ui-motion` / `ui-backdrop` / `ui-fontsize`） | 按钮点了不留存、刷新即丢，或首帧闪烁 |
| b3 | 开关**接到生效规则**：`:root[data-backdrop="off"] .backdrop{display:none}` 与 `:root[data-fontsize="large"] body{font-size:var(--fs-…)}` 必须真实存在 | "看起来能点但什么也不做"的装饰性按钮 |
| c | 根入口 `h1` 行宽预算：`(汉字数 + 0.55×其他字符) × fs上界 × (1+letter-spacing) ≤ 内容列宽`，且两端留白 ≥ `--space-4` | 标题折行 / 两端贴边 |
| c′ | 预算算式**与 CSS 同源**：`--container` / `--rail-w` / `--space-5` 必须真的出现在 `.layout` 限宽、栅格列宽、正文列内边距上 | "算式为真而布局为假"（判据与对象脱钩） |

★ b2/b3 是**"开关可用"与"开关不是装饰"的分界**：只断言按钮存在，等于只断言"画了四个开关"。

★ 取值全部**现读**：`fs` 上界从 `site-palette.values.fs.hero` 取（`clamp` 末项）、
`letter-spacing` 从产物 CSS 的 `h1` 规则取、三个长度令牌从调色板取 ⇒ 改任一值判据立刻跟着变，
⛔ 无任何写死的 48 / 804 / 0.035。取值失败（形态不认识）时判据**直接报 FAIL**，⛔ 不按 0 处理。
