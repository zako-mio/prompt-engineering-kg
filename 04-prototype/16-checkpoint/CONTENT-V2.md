## 1. 页面骨架（所有内容页）

```
h1            纯中文名（一行；⛔ 不含英文、不含括号）
.page-en      英文名（独立一行，无括号）
.meta-line    身份行：节点号 · 内容状态 · 分组 · 依赖层        ← 只放「身份」
.tag-row      标签行：全部 tags                                ← 只放「标签」
.read-map     本页导读：一句话结论 + 八个区块的锚点跳转        ← 先给结论，再给地图
.fig          本页自制图：内联 SVG + 图注 + 「本站自制」溯源    ← 知识承载页 ≥1（R-07）
```

**「一行只干一件事」**：身份、标签、元信息各自独占一行容器；⛔ 不得把 tags 塞进 `.meta-line`。

## 3. 切分口径（⛔ 必须写死，否则判据无法复现）

1. **句子**：与 `gate_prototype.sentences()` 同源 —— `re.split(r"(?<=[。！？!?])", s)`。
   ⛔ 不按逗号切（会把一句话切成碎片）。
2. **总结 / 细节**：按**全角冒号「：」**切一次（`partition`），左＝总结，右＝细节。
   ⛔ 不切分则整条原样进「细节」列（⛔ 不得因此判 FAIL —— 数据本就允许无冒号）。
3. **适用边界**：只在出现显式标记 `适用边界是` 时切出；⛔ **不做关键词猜测**
   （HANDOFF-R2 §三 记的实测教训：「…而是边界：」是主题词，正则误捕）。
4. **术语**：`术语（English）：界定` —— 按「（」「）」取英文、按首个「：」取界定；
   界定须能在 `glossary.json` 解析（P07 原有断言不变）。

## 5. 字号控件（反馈 #5 的正面回答）

**为什么此前"部分生效"**：大档只改了 `body` 的 `font-size` ⇒ 只有**继承 body 字号**的元素（正文段落、列表、卡片文字）变大；标题/导航/标签/表格各自走 `--fs-*` 令牌 ⇒ 不动。这不是 bug，是作用域选择，但它**让层次比例失真**（正文变大而标题不变）。

**改为全生效的正确做法**：把**布局令牌 rem 化**，再改**根字号**：

| 令牌 | 原值 | 新值 | 说明 |
|---|---|---|---|
| `--container` | `1120px` | `70rem` | 16px 根字号下 = 1120px（逐像素不变） |
| `--rail-w` | `252px` | `15.75rem` | = 252px |
| `--nav-h` | `64px` | `4rem` | = 64px |
| `--space-1..7` | `4/8/16/24/32/48/64px` | `0.25/0.5/1/1.5/2/3/4rem` | 同上，逐值等价 |

⇒ 大档＝根字号 `1.125rem`（16→18px），**全站等比放大**：字号、间距、栏宽、内容列宽一起缩放，
层次比例**逐字不变**；根入口 h1 的行宽预算与内容列宽同比缩放 ⇒ P34 的余量比例不变（恒成立）。

## 8. 高可读性设计的**研究结论**（2026-10-15，用户提供 AI 搜索产出后）

> 用户随反馈附来一份 AI 搜索产出（结构化 / 视觉组块化 / 认知脚手架 / 动态检索四策略 + 若干组件建议）。

### 8.1 本地检索底座（`design-material-library`）的结论

按该 skill 的三步取用跑了 5 组关键词（长文 / 目录 / 折叠 / 表格 / 暗色）。**结果如实登记**：

- 库内 **36 条 / 18 个界面单元，无一条直接回答「高可读性长文页」**。最近的是 `N2-1 博客` 的
  `tailwind-nextjs-starter-blog-mdx`（Next.js + MDX + Contentlayer2 长文站）。
- 该条目的 **`F07 不适合情形` 明载**：*「要求零构建、不引入 Node 构建链的纯静态页场合」不适合*
  ⇒ **它的实现方式对本站不可移植**（本站是零构建静态页，P09 断言自包含）。
- 可移植的只有它的**功能清单**：标题锚点、代码高亮、明暗主题、标签页、目录。这些本轮全部手写在
  HTML/CSS 里（锚点 + `<details>` + 令牌化主题 + `.tag-row`）。
- ⇒ 结论：**主流参照实现几乎都建立在构建链上**，而本站的零构建契约把它们全部排除。这不是障碍，
  是**约束下自研**的正当理由；`design-material-library` 的 `F08 工具可达性` 与 `F23 做法可移植性`
  两栏正是为此而分列。

### 8.3 如实登记的研究缺口
