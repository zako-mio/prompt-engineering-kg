# G04 编排

- 英文名：Orchestration
- 分区序号：4
- 组内节点：8 个（已写满 0）
- 层范围：第 8 – 15 层

## 本组导读

本组讲把单次调用组织成系统：提示词链、路由、并行化与投票、编排者—工作者、生成者—评估者、状态机与持久化、子 Agent 上下文隔离，以及工具定义与滥用治理。重点是每种模式当前的定位与代价——多 Agent 系统的 token 消耗远高于普通对话，固定链式编排已收窄为「需要检查中间产物时」的选项，而工具定义本身就是提示词面的一部分。读者应能按任务是否需要固化中间产物、是否需要并行探索来选择模式。

## 本组学习路径

### 第 8 层

- PE-O-01 提示词链（Prompt Chaining）

- 为什么在这层：PE-O-01 ← PE-R-02（PREREQ）先知道模型内部已能处理多步推理，才能理解链条为何收窄

### 第 9 层

- PE-O-02 路由（Routing）

- 为什么在这层：PE-O-02 ← PE-O-01（PREREQ）链是单一路径的流程，路由是在多条路径之间选择

### 第 10 层

- PE-O-03 并行化与投票（Parallelization and Voting）

- 为什么在这层：PE-O-03 ← PE-O-02（PREREQ）路由决定走哪条路，并行化决定每条路上是否同时跑多份

### 第 11 层

- PE-O-04 编排者—工作者（Orchestrator–Workers）

- 为什么在这层：PE-O-04 ← PE-O-03（PREREQ）先掌握并行与聚合，再引入需要拆解与汇总的多工作者结构

### 第 12 层

- PE-O-05 生成者—评估者（Generator–Evaluator）

- 为什么在这层：PE-O-05 ← PE-O-04（PREREQ）编排者—工作者解决拆分，生成者—评估者解决质量把关

### 第 13 层

- PE-O-06 状态机与持久化（State Machine and Persistence）

- 为什么在这层：PE-O-06 ← PE-O-05（PREREQ）先有评估与迭代，才需要把迭代过程固化为可恢复的状态

### 第 14 层

- PE-O-07 子 Agent 上下文隔离（Sub-agent Context Isolation）

- 为什么在这层：PE-O-07 ← PE-O-06（PREREQ）状态是跨调用的事实，子 Agent 隔离是跨上下文的边界，两者配套

### 第 15 层

- PE-O-08 工具定义与滥用治理（Tool Definition and Abuse Governance）

- 为什么在这层：PE-O-08 ← PE-O-07（PREREQ）子 Agent 能做什么由工具定义决定，故先学隔离再学工具治理
