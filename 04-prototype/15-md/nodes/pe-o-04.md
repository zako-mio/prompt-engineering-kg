# 编排者—工作者（Orchestrator–Workers）

- 节点标识：PE-O-04
- 英文名：Orchestrator–Workers
- 所属分组：G04 编排
- 依赖深度：第 11 层
- 内容状态：内容已写满
- 标签：编排、多 Agent、成本

## 为什么需要它

编排者—工作者模式由一个主 Agent 拆解任务、多个工作者并行执行、最后汇总，适合可并行探索的复杂任务。它的成本结构需要被正视：多 Agent 系统的 token 消耗远高于普通对话，因此只有在任务价值足以覆盖成本时才值得使用。

**适用边界**

拆分必须做到信息自包含，否则工作者会重复探索或产出互相冲突的结论；在子任务强耦合的场景下，该模式会放大而不是消解协调成本。

## 机制说明

该模式的实现要素有四个：拆解策略（按什么维度切分任务）、工作者契约（每个工作者收到什么、回传什么）、汇总策略（如何合并冲突结论）、以及预算控制（并发数与总轮数）。官方多 Agent 实践给出的量化口径是：多 Agent 系统相对普通对话的 token 消耗约十五倍，普通 agent 相对对话约四倍——这决定了该模式的适用范围是「并行探索能带来实质增益」的任务，例如需要多角度检索与交叉验证的研究型任务。同一份官方实践也给出了收益侧的数字：以主 Agent 加子 Agent 构成的多 Agent 系统，在内部研究评测上的成绩比同等单 Agent 高出 90.2%。

## 何时该用 / 何时不该用

- 任务可并行探索、且多角度交叉验证能带来实质增益时：该模式值得其成本。
- 子任务可做到信息自包含时：工作者之间不需要频繁通信，协调成本可控。
- 不适用于子任务强耦合的场景：拆分后仍需大量通信，协调成本被放大。
- 不适用于成本敏感的高频调用：多 Agent 的 token 消耗量级不适合高频路径。

## 实验台

### prompt（markdown）

```markdown
你是编排者。按下列顺序处理用户任务，不要跳步。

1. 用一句话写出总目标，并写出这次任务的验收条件（可判定的那种，不写「质量好」）。
2. 按「可独立取证」这一维度把任务拆成 2–4 个子任务。每个子任务必须写明四件事：输入材料、约束、产出格式、失败时回传什么。
3. 每个子任务单独发起一次委派，禁止把两个子任务的指令合并进同一次委派。
4. 汇总时逐条比对子任务结论：一致的写结论并附来源；互相冲突的写「冲突」并列出双方依据，不得取折中表述。
5. 输出固定四段：最终结论 / 每个子任务的来源 / 未解决项 / 实际消耗的子任务数。

预算：子任务数 ≤ 4，总委派轮次 ≤ 2 轮；超预算时停下来回报，不要自行加派。
```

预期观察：在同一任务上跑两遍，两遍产出的子任务数都不超过 4，且最终结论的每一条都能对应到某一次委派的返回；出现无来源结论或子任务数大于 4 即为不通过。

### file（markdown）

```markdown
# 工作者任务卡（每次委派复制一份，只填这一份）

## 背景（子 Agent 看不到主对话，这里必须自包含）
- 目标：
- 已知事实：
- 明确不要做的事：

## 约束
- 预算：最多调用 N 次工具 / 最多 N 分钟
- 允许的信息来源：

## 产出格式（缺任何一段，该次委派判为失败）
1. 结论：一句话，脱离主对话也能读懂
2. 依据：逐条列出，每条形如「结论片段 ← 出处」
3. 未解决项：列出，或写「无」
4. 置信度：高 / 中 / 低 + 一句理由

## 失败处理
拿不到材料时不要猜，直接回报「缺什么、卡在哪一步」。
```

预期观察：把这张卡交给一个没有主对话上下文的子 Agent，它能在不回问的情况下产出四段结构；四段中缺任一段，或结论里出现「见上文」，即判该次委派失败。

## 证据

- **官方多 Agent 研究系统的实测显示，主 Agent 加子 Agent 的组合在内部研究评测上比同等单 Agent 高出 90.2%。**（S-0006，official）
  - 出处：https://www.anthropic.com/engineering/multi-agent-research-system
  - 原文关键句：a multi-agent system with Claude Opus 4 as the lead agent and Claude Sonnet 4 subagents outperformed single-agent Claude Opus 4 by 90.2% on our internal research eval.
- **多 Agent 系统的 token 消耗约为普通对话的 15 倍、单 Agent 约为 4 倍，成本量级必须在选型时先算清。**（S-0006，official）
  - 出处：https://www.anthropic.com/engineering/multi-agent-research-system
  - 原文关键句：agents typically use about 4× more tokens than chat interactions, and multi-agent systems use about 15× more tokens than chats.
- **官方把多 Agent 架构的适用面限定在「并行探索有收益」的复杂研究与分析任务上，而非所有任务。**（S-0004，official）
  - 出处：https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
  - 原文关键句：Multi-agent architectures handle complex research and analysis where parallel exploration pays dividends.

## 术语

- **编排者—工作者（Orchestrator–Workers）**：由编排者拆解任务并把子任务分派给多个工作者，最后汇总结果的编排模式。
- **子 Agent 上下文隔离（Sub-agent Context Isolation）**：让子 Agent 在独立上下文中完成子任务、只把结论回传主 Agent，以避免主上下文被过程细节污染。

## 失效模式

- 按「章节」而不是按「可独立取证」拆任务：子任务之间仍要共享同一批材料，工作者各自重复检索，汇总时结论互相矛盾。
- 工作者契约只写目标不写产出格式：回传内容长短不一，编排者无法机械比对，只能重读全部过程，隔离省下的上下文又被读回来。
- 并发数按「越多越快」设：token 消耗随工作者数量线性放大，而整体延迟受最慢一路约束，预算往往先于结论耗尽。
- 汇总时对冲突结论取折中表述：两方证据都被削平，最终结论不被任何一路支持，事后也无法回溯到具体依据。

## 一句话小结

该模式只在并行探索有实质增益时划算，拆分必须做到信息自包含。
