## 2. ★ 本轮新建立的三条机制（下一轮要照着用，⛔ 不要重犯它的坑）

### 2.1 「判据对象 ≠ 断言对象」的**撞一次**纪律（本轮的 G42，最值钱）

本轮 6 条实测缺陷里 **4 条**属同一形态：判据的**对象**大于它的**断言对象**。
它们**全部潜伏至今**，因为「对象过宽」在**存量产物**上恰好不触发：

| 例 | 对象过宽的表现 | 为什么存量不触发 | 什么时候炸 |
|---|---|---|---|
| P09 | 把**一切** `<link>` 当加载类资源 | 存量页本来没有 `canonical` | SH4 一落地 |
| P12 | 对**属性值**与 sitemap/robots 的 **URL 载荷**判「主机名」 | 存量页本来没有绝对 URL | 同上 ＋ `README.md` 一进发布面 |
| P13 | `counts.md` 取 `len(ctx.md)`（含手写 README）而生成器算的是**镜像数** | README 本来不在发布面 | `README.md` 一进发布面 |
| P12 | 未把 `README.md` 算作**元数据面** | 同上 | 同上 |

★ **可复用纪律**：判据的对象边界必须用「**下一个会加进来的东西**」去撞一次
（本轮的做法是先写 `_probe/r8_t1_p09_probe.py`，把 SH4 的形态**合成进内存**再调判据函数），
⛔ **不能靠「存量全绿」证明它对**。★ 下一轮每次要新增一类产物/字段，先问：**哪条判据的对象会因此变宽？**

### 2.2 分档 CI（`16-checkpoint/_ci_gate.sh`）

- `fast`（每次 push）：`gate_prototype.py --only <子集>` ＋ A 段 ＋ S 段，各带 `--selftest`。
- `full`（`workflow_dispatch` ＋ 每周一）：P01–P41 ＋ `--selftest` ＋ 数据自检 ＋ 图件规格探针。

★ **实测发现（G43）**：跑子集**不是「少跑一点」，它会换一个扫描面** ——
本轮 P13 与 P12 的两条缺陷**只在 fast 档被翻出来**（full 档此前也绿）。
⇒ 下一轮改判据后**两档都要真跑**，⛔ 不得只跑一档就说"全绿"。

### 2.3 发布面是**显式对象集**（`.github/workflows/pages.yml` 的「装配发布目录」步）

发布面**不是** `cp -r 04-prototype/`，而是逐项列出的：`assets` `10-dag-data` `11-node-pages`
`12-groups` `13-interactive` `14-views` `15-md` ＋ `index.html favicon.svg og.png robots.txt sitemap.xml .nojekyll`。
⇒ `16-checkpoint/`、`PUBLISH-STATE.json`、`README.md` **不上线**（CI 有「覆盖完备性」步守着）。
★ 下一轮若新增产物目录/文件，**必须同步改这张清单**，否则新产物不会上线（⚠ 且**不会有任何报警**）。
