01为什么需要它

思维树与思维图把线性推理扩展成可分叉、可回溯、可合并的结构，用于确实存在搜索空间的任务。

  • 它们当下的问题不是能不能用，而是代价与收益不再匹配：原生推理已覆盖多数多步推导，显式搜索的调用次数却随分支数与深度相乘放大，不同研究对固定探索策略的有效性还给出冲突结论。
  • 掌握本节点是为了判断哪些任务真的需要显式搜索结构，而不是把它当成进阶技巧优先采用。

适用边界

本节点界定的是推理结构这类实现方式的适用条件，而不是一个可以直接套用的提示词模板。它不覆盖单轮直接作答即可完成的任务，也不覆盖缺少任何判据、只能随机重试的展开。另外，厂商现行文档不收录 ToT 与 GoT 这两个技术名，这只说明证据缺席，不能据此判定它们已被证伪。

02机制说明

思维树的基本形态是在每一步生成多个候选思维，由评估环节打分或判可行性，再按搜索策略展开或剪枝，从而把一次性作答变成一次受预算约束的搜索。

  • 思维图进一步允许中间结果合并与复用，把树扩展为图，在可聚合的任务上能同时提升质量与降低成本。
  • 两者的工程成本集中在三处：候选生成与评估的调用次数、搜索策略的调参、以及评估偏移导致的过剪枝或死锁。
  • 最新研究还指出不存在跨计算预算都适用的固定探索与剪枝策略：一种方法在低预算下受冷启动瓶颈限制，另一种方法的激进合并会永久丢弃未探索路径。

03何时该用 / 何时不该用

按场景对照：先看条件，再看该怎么做。
类别场景 / 条件（总结）具体做法（细节）
该用任务存在真实分支空间且评估环节可靠时例如带硬约束的规划与组合问题，显式搜索才可能有增益。
该用中间结果可复用与可聚合时图结构让同一中间结论被多次引用，相对树结构有成本优势。
不该用把搜索当进阶默认项调用次数随分支数放大，厂商现行文档也不收录这类技术名。
不该用评估环节不可靠的场景评估偏移会导致过剪枝，或在合并时永久丢弃未探索路径。

04实验台

  1. shellpython

    查看代码
    # 预算受限的思维树骨架：每步展开 k 个候选，评估后只保留前 m 个
def tot_search(state, expand, evaluate, k=3, m=2, budget=12):
    calls = 0
    frontier = [state]
    while frontier and calls < budget:
        nxt = []
        for s in frontier:
            for c in expand(s, k):          # 候选生成：一次调用产出 k 个候选
                calls += 1
                nxt.append((evaluate(c), c))  # 评估：打分或判可行性
        nxt.sort(key=lambda x: -x[0])
        frontier = [c for _, c in nxt[:m]]   # 剪枝：只保留前 m 个
    return frontier[0][1] if frontier else None, calls

    预期观察：调用次数始终受 budget 封顶，不随分支数 k 无限放大；把 m 从 2 调到 1 会提高剪枝强度并丢掉未探索路径，因此每次运行都要打印 calls 与最终保留候选数，才能把结果与预算、剪枝强度一起记录。

  2. promptmarkdown

    查看代码
    你是候选思维评估者。对每个候选只做一件事：判断它是否满足给定约束，并给出 0 到 1 的分数。

约束：<在此逐条列出可判定的硬约束>
候选：<候选思维列表>

输出格式（每个候选一行）：
候选编号 | 分数 | 依据（引用被违反或满足的具体约束）
若无法判断，分数写 unknown，并说明缺少哪条信息。不要为了给出分数而猜测。

    预期观察：输出可被程序解析为分数与依据；出现 unknown 的候选说明评估不可靠，此时应停止剪枝并补信息，而不是把 unknown 当作低分砍掉。

06术语

术语思维树　Tree of Thoughts, ToT

界定把推理展开为树状搜索，允许在中间节点生成候选、评估与回溯剪枝的推理结构。

相关节点—

术语思维图　Graph of Thoughts, GoT

界定把推理中间结果表示为可任意合并与聚合的图结构，相较树状结构允许节点复用与结果合并。

相关节点—

术语生成者—评估者　Generator–Evaluator

界定由生成者产出、评估者按明确判据给出反馈并驱动迭代的编排模式，适用于有清晰评价标准的任务。

相关节点—

07失效模式

  • 把显式搜索当默认进阶项调用次数随分支数与深度相乘放大，多数任务上的收益不足以覆盖这份成本。
  • 评估函数不可靠就开始剪枝评估偏移会砍掉正确分支，最终以高置信度收敛到错误答案。
  • 只报最优结果、不记预算与剪枝强度同一方法在低预算与高预算下结论相反，事后既无法复现也无法归因。
  • 候选展开不设上限没有最大分支数与最大调用数的封顶，长尾任务的成本与延迟不可预测。
