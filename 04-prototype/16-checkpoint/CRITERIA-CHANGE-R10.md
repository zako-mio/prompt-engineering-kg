## 2. 裁决表

### 2.1 新增 `P42` 内容状态文案与真相源一致（硬判，**进 push 档**）

| 项 | 裁决 |
|---|---|
| 对象 | 全部 HTML 页的**可见文本**（剥 `<style>/<script>/注释/标签`）＋ 真相源 `dag.json` 的 `content_status` |
| 断言 ① | 任何状态下不得出现「架构在册 **0**」「内容待填充 **0**」这类归零残留（口径用正则 + `0` 后不得紧跟数字） |
| 断言 ② | 首页自报「已写满 N 个」必须 `==` 真相源 complete 数；有 registered 时首页「架构在册 N 个」也必须 `==`；学习路径页「已写满 N」同样对账 |
| 断言 ③ | **单态**（`registered == 0`）时，全站可见文案不得再出现「架构在册」「内容待填充」两态语汇 |
| 负例 | 2 条：① 首页自报数被改小 1（数字脱钩）② 任意页注入「架构在册 0 个」 |
| 为什么是硬判而非报告项 | 句子层面「自相矛盾」是可机检的；而「读起来是否啰嗦」不可机检（那留给 `P35` 的报告项） |

★ 产物侧的配套改动（**先改产物、后加判据**违背纪律，本次是**同批**）：新增
`gen-common.content_state_copy()` 单一出口，5 个生成器全部改读它；`gen-common.state_counts()` 缓存计数。

### 2.2 新增 `P43` 图注跨登记表逐字同文（硬判，**进 push 档**）

| 项 | 裁决 |
|---|---|
| 对象 | `gen-figs.py` 的 `FIGS[fid].caption`（AST 解析，⛔ 不 import——import 会渲染）与 `gen-nodes.py` 的 `NODE_FIG[nid] = (fid, caption)` |
| 断言 | 每条 `NODE_FIG` 的 `fid` 必须在 `FIGS` 里；两处 caption **逐字节相同**；两边都不得为空集 |
| 负例 | 2 条：① 把某条 caption 追加「（夹具改动）」② 把图 id 改成不存在的 `pe-xxxxZZ` |
| 为什么必须逐字 | 「同一句说明写两处」是本仓最贵的漂移面（与 `P42` 同族）；而「哪一句更好」不可判，故只判**一致**，⛔ 不判措辞 |

### 2.3 数据侧新增 `C59` 双载体一致（`_selfcheck.py`，不入门控 59 条计数口径）

## 4. 局限登记（⛔ 不得读作已覆盖）

1. `P42` 只判**首页 / 学习路径页 / 零注册残留**三处；组页、节点页、交互页的「已写满」字样**不在断言面内**
   （它们在单态下不出现，但没有判据守着）。⇒ 登记为缺口。
2. `P42` 断言的数字对账只覆盖**两页**；`sitemap.xml`、`PUBLISH-STATE.json` 的数字由生成器保证，无判据交叉核对。
3. `P43` 只判「两处字面量一致」；⛔ 判不了「这句 caption 是否准确描述了那张图」（那是语义面，归视觉核查）。
4. `C59` 只判身份层（id / 标题前缀 / evidence 非空）；两处**正文口径相反**这件事它**判不出来**。
5. `gate-manifest.json` 自身仍**没有**判据校验「编号集合 ⟺ 实现」（第 8 轮起的 `not_covered` 原样留行）；
   本轮只消掉了**夹具数**这个重复事实，没有消掉**编号集合**这一层。

## 5. 纪律自陈

- **同批**：产物侧（`content_state_copy` / `pe-f-06` caption / `frontier.json` 两片）与判据侧（`P42` / `P43` / `C59` / `C58b` 分支）
  在**同一次改动内**落地，⛔ 没有「先改产物、后补判据」的时序。
- **可判假**：两条新判据各有 2 条负例，且 `P43` 在**引入当天就报出真实存量缺陷**（不是全绿之后补的）。
- **不降级**：`C58b` 的改动方向是「0 坏 → 不再 WARN」，⛔ 不是「有坏 → 放过」。`C58` 的 fail-closed 语义一字未动。
- **不重复事实**：`K2` 处置方式是把清单里的数字**删掉**并指向脚本结论行，⛔ 不是把 176 改成 178（那会在下次继续漂）。
- **诚实边界**：§4 的五条局限是本轮**已知的未覆盖**，⛔ 不得用「三套门控全绿」把它们的缺口压掉。
