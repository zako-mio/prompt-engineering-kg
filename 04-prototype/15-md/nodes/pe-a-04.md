# 过拒与安全—可用性权衡（Over-refusal and the Safety–Usability Tradeoff）

- 节点标识：PE-A-04
- 英文名：Over-refusal and the Safety–Usability Tradeoff
- 所属分组：G06 安全与鲁棒性
- 依赖深度：第 16 层
- 内容状态：内容已写满
- 标签：安全、过拒、可用性

## 为什么需要它

把拦截率当成安全工作的唯一成绩单，会系统性地奖励「多拦一点总没错」：每一次收紧阈值都能让拦截率上升，而代价要到用户正常请求被拒时才浮现，且很容易被记成个案抱怨。过拒率的作用就是把这份代价放到同一张表上——它不反对安全策略，只要求安全收益与可用性损失被同时读出。缺少这一侧读数，安全调优会朝过度保守单向漂移，而且漂移过程全程无声：没有任何一条监控会因为「今天比昨天多拒了几次正常请求」而报警。

**适用边界**

过拒率是可操作指标而非行业常数：它的数值取决于样本构成、判据口径与业务对风险的接受度，因此不同系统之间的过拒率不可直接横比，只能看同一系统在改动前后的自身变化。测量本身也有前提：用于估算过拒率的正常请求样本必须带人工或可判定的标签，样本量太小时抽样噪声就会被误读成策略回退或改进。

## 机制说明

过拒的成因通常落在三处。第一处是拦截粒度：安全分类器把整段内容判为可疑，一处可疑文本就让整个任务失败。第二处是安全指令的形态：提示里写着遇到任何可疑内容即中止，规则绝对且没有分层。第三处是冲突处置：层级冲突或来源可疑时一律拒绝，而不是降级执行。改进方向与成因一一对应：把拦截粒度做细，只剔除可疑片段而非整段作废；把安全指令改写成可判定的处置规则，让继续、降级、中止成为三种明确结果；为可降级的场景预留降级路径。度量侧必须成对记录：攻击成功率与正常请求拒绝率同表，并定期用正常流量样本估算过拒率；只优化一侧必然把系统推向某个极端。这条权衡的代价在近期证据里可以直接读到：有工作把过拒率压到标准偏好优化的一半而优先关系反而提高，也有工作在攻击成功率上取得数倍下降而效用不明显受损，但同一族的训练还伴随偏好得分与对话胜率的回退，说明安全侧收益很少零成本。

## 何时该用 / 何时不该用

- 链路需要读取外部内容且任务不宜整体失败时：把安全拦截做成分段处置，并单独度量过拒率。
- 安全策略或分类阈值发生改动后：用固定批次的正常流量样本复跑一遍过拒率，确认可用性没有无声退化。
- 需要论证某次收紧是否值得时：把攻击成功率的下降与过拒率的上升写进同一份报告，再交给业务侧判断。
- 不适用于把过拒率当跨系统横比指标：样本构成与判据口径不同，数值之间没有可比性。
- 不适用于无差别压低过拒率：高风险场景接受更高过拒率可以是正确的取舍，但必须是有意识的取舍。

## 实验台

### shell（bash）

```bash
# 同一批正常请求样本，在「收紧前 / 收紧后」两版安全配置上各跑一遍
# 样本目录：benign/*.txt（人工确认为正常请求）；判据：被拒即计一次误拒
for v in before after; do
  python3 - "$v" <<'PY'
import glob, json, subprocess, sys
v = sys.argv[1]
bad = []
for f in sorted(glob.glob("benign/*.txt")):
    r = subprocess.run(["python3", "ask.py", "--safety", v, "--input", f],
                       capture_output=True, text=True)
    if json.loads(r.stdout).get("refused"):
        bad.append(f)
print("config=%s 误拒=%d/%d" % (v, len(bad), len(glob.glob("benign/*.txt"))))
PY
done
# 另跑一批恶意样本，输出同表：拦截率 / 过拒率两列都必须在报告里
python3 - <<'PY'
import json
s = json.load(open("adversarial-report.json"))
print("拦截率=%.1f%% 过拒率=%.1f%%" % (100*s["block_rate"], 100*s["over_refusal_rate"]))
PY
```

预期观察：两版配置各自打印出误拒计数；若「收紧后」的拦截率上升而误拒计数同时跳升，说明这次收紧把可用性损失换成了安全收益，必须把两个数字一起写进报告再决定是否保留。命令输出里缺过拒率一列的版本不予采纳。

## 证据

- **过拒率是可量化的训练侧指标：该工作在多级指令层级上同时提高优先级遵循并把过拒率压到标准 DPO 的一半，说明「更守层级」与「更少误拒」并非只能二选一。**（S-0041，paper）
  - 出处：https://arxiv.org/abs/2606.10860
  - 原文关键句：We formalize a k-level instruction hierarchy problem and instantiate it for k=5 ... raising macro pairwise priority adherence while keeping over-refusal at half the standard DPO rate.
- **安全—可用性权衡的代价在厂商自述数据里可见：指令层级增强让对抗类指标明显上升，但同期对话胜率与偏好得分出现回退，因此安全侧收益必须以成对指标呈现，不能只报上升的那一列。**（S-0017，vendor）
  - 出处：https://openai.com/index/instruction-hierarchy-challenge/
  - 原文关键句：OpenAI's models are trained to follow a clear instruction hierarchy: System > developer > user > tool ... Chat WinRate vs o1 0.71 → 0.66 (-0.05); Preference Score 0.46 → 0.40 (-0.06).
- **把防御下沉到模型内部表示层可以把梯度类注入攻击的成功率压低数倍，这为「不必靠整段拒绝来换安全」提供了可引用的技术路线；其代价是该方法需要训练或微调，不属于纯提示词手段。**（S-0042，paper）
  - 出处：https://arxiv.org/abs/2505.18907
  - 原文关键句：our proposal yields between 1.6x and 9.2x reduction in attack success rate on gradient-based prompt injection attacks

## 术语

- **过拒（Over-refusal）**：安全策略过严导致正常请求被拒绝的现象；它与拦截率构成安全—可用性权衡，须双向度量而非只优化一侧。

## 失效模式

- 整段拦截：一处可疑文本就让整个任务失败，用户看到的是能力缺失而不是安全提示，正确内容被一并丢弃。
- 安全指令绝对化：提示里写「遇到任何可疑内容即中止」，模型只能二选一，本来可降级完成的请求被整体拒掉。
- 只报拦截率：报告缺过拒率一列，把正常请求被拒计成安全收益，防御在多次调优后整体偏严而无人察觉。
- 把过拒率当横向排名：不同系统的样本构成与判据口径不同，跨系统比数值会得出无法复现的结论。
- 用无标签流量估算过拒率：缺少人工或可判定标签，抽样噪声被当成策略回退，每次都按噪声改配置。

## 一句话小结

安全策略要同时报拦截率与过拒率两列，把处置拆成继续、降级、中止三种可判定结果；权衡的落点由业务风险决定，并须留下取舍记录。
