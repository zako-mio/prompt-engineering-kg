## 为什么需要它

机械断言只能覆盖可枚举的输出形态，而风格、完整性、可用性这类质量标准没有唯一答案可用等式判定，模型即裁判因此成为把主观标准工程化的主要手段。代价是评分权被交给一个自身带系统性偏差的模型：候选顺序、回答长度、是否同族都会稳定影响打分，偏差还会随底座模型更新而漂移。不掌握这些偏差就使用模型裁判，等于拿一把会移动的尺子做回归比较。

**适用边界**

模型裁判的定位是相对比较与粗筛，不是唯一判据：同批次内的排序信息比绝对分数可信，跨批次、跨模型的分数不可直接比较。高风险与合规判定必须由确定性断言或人工抽检兜底。裁判的偏差也会随底座模型换代而变化，因此准则与校准样例要随模型更新重新验证，不能一次校准长期沿用。

## 机制说明

常见偏差有四类。位置偏差：同一对候选只调换顺序，评分就会变，缓解手段是随机化顺序或双向各评一次后取平均。冗长偏好：更长、更结构化的回答更容易被给高分，缓解手段是把「长度不计分」写进准则或做长度归一。自我偏好：裁判倾向给同族模型的输出高分，缓解手段是换用不同家族的模型交叉评分。准则漂移：同一份准则文本在不同批次被理解得不一致，缓解手段是固定准则文本并附少量已校准的示例。工程做法是把模型裁判与确定性断言并用：能用相等、包含、正则、JSON 合法性判定的部分绝不用模型裁判；必须用模型裁判时，固定准则文本、随机化候选顺序，并在小样本上与人工标注算一致率。每次评分都要保留原始分数与理由，便于事后复核与重新校准。

## 何时该用 / 何时不该用

- 评价维度落在风格、完整性、可用性等无法机械判定的质量标准上时：用模型裁判，并把准则写成可判定的条款。
- 需要在大量候选之间做相对排序或粗筛时：先用模型裁判缩小范围，再对头部候选做确定性断言或人工复核。
- 不适用于把裁判分数当绝对度量：跨批次、跨模型的分数不可比，只能解释为同批次内的相对高低。
- 不适用于高风险或合规判定：这类结论必须由确定性断言或人工抽检给出，模型裁判只能作为辅助信号。

## 实验台

### prompt（markdown）

```markdown
你是评分裁判。按下面三条准则给候选回答打分（1–5），准则与权重固定，不得新增准则：
1. 是否回答了问题本身
2. 是否包含无法核实的断言
3. 是否可直接执行（格式与必需字段齐全）
输出 JSON：{"score": <1-5>, "reason": "<不超过两句，须引用候选回答中的原文片段>"}
注意：长度不计分；本候选的分数与它在列表中的位置无关。
```

预期观察：裁判返回分数与理由，且理由必须引用候选原文，便于事后复核。把同一对候选换序再评一次：若分数发生变化，说明该批次存在位置偏差，必须随机化顺序或双向取平均后再写进基线。

### shell（bash）

```bash
# 顺序随机化 + 双向复评：同一对候选各评两次（A/B 与 B/A），比较两次判定是否一致
for order in ab ba; do
  npx promptfoo@latest eval -c judge-$order.yaml --output run-$order.json --no-cache
done
python3 - <<'PY'
import json
load = lambda p: {t["id"]: t["score"] for t in json.load(open(p))["results"]}
a, b = load("run-ab.json"), load("run-ba.json")
flip = [k for k in a if a[k] != b.get(k)]
print("顺序敏感样本：%d / %d" % (len(flip), len(a)))
PY
```

预期观察：打印顺序敏感样本数：计数为 0 表示本批次未见位置偏差；计数为正时必须随机化顺序或对两个方向取平均后再比较，不得直接把单方向的分数写进基线台账。

## 证据

- **评测工具把断言分成两族：确定性指标（相等、包含、正则、JSON 合法性等）与模型辅助指标（llm-rubric、g-eval 等评分型裁判）；本节点主张的「能用确定性断言判定的部分绝不用模型裁判」因此有可落地的工具面支撑，而非纯口头约定。**（S-0077，official）
  - 出处：https://www.promptfoo.dev/docs/configuration/expected-outputs/
  - 原文关键句：Deterministic eval metrics: equals / contains / icontains / regex / is-json … Model-assisted: similar / classifier / moderation / llm-rubric / g-eval
- **官方把 evaluator-optimizer（生成者—评估者）列为五种工作流模式之一：评估者是编排回路中的独立角色，其判断直接决定迭代方向，因此裁判偏差会沿回路放大，必须被单独控制。**（S-0005，official）
  - 出处：https://www.anthropic.com/engineering/building-effective-agents
  - 原文关键句：Workflows are systems where LLMs and tools are orchestrated through predefined code paths. … Parallelization (Sectioning / Voting) … Orchestrator-workers … Evaluator-optimizer.
- **位置类偏差的强度不是常数：在长上下文检索场景中，输入占上下文窗口比例超过约一半后，首因偏差减弱而近因偏差保持稳定，原本的中间位置效应被距离型偏差取代 ⇒ 位置偏差需按输入规模重新标定，不能当作固定的分数偏移量。**（S-0064，paper）
  - 出处：https://arxiv.org/abs/2508.07479
  - 原文关键句：the LiM effect is strongest when inputs occupy up to 50% of a model's context window. Beyond that, the primacy bias weakens, while recency bias remains relatively stable.

## 术语

- **模型即裁判（LLM-as-a-Judge）**：用模型按评分准则对输出打分或排序的评测手段；存在位置偏差、冗长偏好与自我偏好等系统性偏差，须与确定性断言并用。
- **生成者—评估者（Generator–Evaluator）**：由生成者产出、评估者按明确判据给出反馈并驱动迭代的编排模式，适用于有清晰评价标准的任务；评估者的偏差会直接决定该回路收敛到哪种质量。
- **评测集（Eval Set）**：带判据的一组代表性输入输出样本，是判断提示词改动是否真的变好的唯一依据；用于校准裁判的样本应与评测集不相交，否则校准即过拟合。

## 失效模式

- 把裁判分数当绝对度量：跨批次、跨模型的分数不可比，回归曲线会出现假性升降。
- 候选顺序固定：位置偏差被固化进基线，一旦改动影响候选生成顺序，就会被误判为质量变化。
- 准则文本随手改动：同一批样本的分数失去可比性，等于每次评测都换了一把尺子，历史结论全部作废。
- 只用同族模型自评：自我偏好会把同源输出的缺陷系统性地评高，掩盖真实退化。
- 校准样本与评测集重叠：裁判在见过的样本上表现很好，换到新样本后一致率回落，而基线已经按虚高的数字定死。

## 一句话小结

模型裁判只当相对比较与粗筛工具用：固定准则文本、随机化候选顺序、保留分数与理由，并用确定性断言或人工抽检兜住高风险判定。
